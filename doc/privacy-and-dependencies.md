# 隐私、配置与第三方依赖

## 配置与运行数据

源码仓库提供可部署源码和配置示例。部署者自己的数据库、网盘内容、消息、日程、课表、采集记录、缓存和设备状态应留在相应的运行环境中。

以下内容不应随源码提交：

- `config.local.json`、实际环境变量文件及包含私有连接的其他配置。
- 签名文件、访问令牌、数据库密码、刷新会话和 API 凭据。
- 数据库文件、备份、网盘存储、微信采集数据和附件。
- 包含真实账户、联系人、消息、日程或部署路径的日志、截图与测试 fixture。
- 本机 `local.properties`、虚拟环境、依赖安装目录、构建输出和带私有配置的历史安装包。

配置示例使用占位连接和通用账号名称。启用集成时自行填写上游服务配置，避免将服务器凭据编译进浏览器文件；Android 通过设置选择自己的 HTTPS 站点。

## 发布范围

源码范围包括后端、数据库迁移、网页客户端、信息中心集成、Android 客户端、部署模板、测试及必要构建附件。运行数据与旧部署验收工件不属于复现功能所需的源代码。

这是独立的脱敏部署快照，特殊存储的账号和配置名已通用化，内部路径前缀为 `_special_storage/`。原部署数据库不随源码提供；如复用其他既有数据库，应先核对存储配置和内部地址映射，不能将它当作原部署的直接覆盖升级包。

构建脚本和 Gradle wrapper 保持可用；签名和交付位置通过本地配置提供。新增构建产物前，应检查其中是否包含实际服务地址、用户配置或私有测试数据。

`.gitignore` 用于防止后续误提交，不会清除已经存在于 Git 历史中的内容。公开发布应同时检查待发布文件与提交历史；本地私有备份和原部署记录需要单独保存。

## 测试资料

自动化测试应使用临时数据库、示例文件及独立设备状态。真实接口验收需要临时账号时，fixture 放在仓库之外，测试完成后清理相应数据。可公开的截图应使用专门的示例数据重新生成，并检查画面文字与图片元数据。
